    Référence G-code et M-code : les codes à connaître par cœur

    Les codes G et M courants (mouvements, plans, unités, compensation, cycles, broche, arrosage) avec leur sens, un exemple commenté et les pièges entre commandes.

    Le G-code (normalisé à l’origine par l’EIA RS-274 et l’ISO 6983) est la langue des machines CNC. Les codes G décrivent la géométrie et les modes ; les codes M pilotent les fonctions machine (broche, arrosage, fin de programme). Chaque commande a son dialecte : ce tableau suit la documentation LinuxCNC, très proche des conventions de type Fanuc, et signale les écarts courants. Votre manuel de commande a toujours le dernier mot.

    Codes modaux : la notion clé

    La plupart des codes sont modaux : ils restent actifs jusqu’à ce qu’un autre code du même groupe les remplace. Un G1 reste actif ligne après ligne ; un G91 oublié rend tout le reste du programme incrémental. C’est la source n° 1 des collisions « inexplicables ».

    Mouvements

    CodeSensNotes
    G0Déplacement rapideVitesse max de la machine ; trajectoire pas forcément en ligne droite sur toutes les commandes
    G1Interpolation linéaire à l’avance FLe mouvement de coupe de base
    G2 / G3Arc horaire / antihoraireCentre en I J K (ou rayon R)
    G4TemporisationP en secondes sur LinuxCNC ; en millisecondes sur certaines commandes de type Fanuc selon le réglage — vérifiez

    CodeSens
    G17 / G18 / G19Plan XY / XZ / YZ (G18 est le plan habituel du tour)

    G90 / G91Coordonnées absolues / incrémentales
    G90.1 / G91.1Centres d’arc I J K absolus / incrémentaux (LinuxCNC, Mach)
    G93 / G94 / G95Avance en temps inverse / par minute / par tour

    CodeSens
    G53Déplacement en coordonnées machine (non modal)
    G54 à G59Systèmes de coordonnées pièce 1 à 6 — voir Décalages d’origine

    G92Décalage de coordonnées « temporaire » — puissant et piégeux, à éviter si vous ne maîtrisez pas son annulation

    Codes M courants

    CodeSens
    M0 / M1Arrêt programme / arrêt optionnel
    M2 / M30Fin de programme (M30 rembobine sur la plupart des commandes)
    M3 / M4 / M5Broche horaire / antihoraire / arrêt — en plasma, souvent torche ON / OFF
    M6Changement d’outil (avec T…)
    M7 / M8 / M9Brouillard / arrosage / arrêt arrosage
    M62–M65Sorties numériques synchronisées ou immédiates (LinuxCNC), utilisées notamment pour le THC plasma

    Attention

    En plasma, chaque commande a ses propres codes pour la torche, le palpage de hauteur (IHS) et le THC : FireControl utilise par exemple H0/H1 selon la documentation Langmuir. Utilisez le post-processeur du fabricant — voir Post-processeurs.

    Ligne de sécurité

    Commencez chaque programme par une ligne qui remet les modes dans un état connu, par exemple G21 G17 G40 G49 G80 G90 (adaptez G20/G21). Elle protège contre les modes laissés actifs par le programme précédent ou par une saisie manuelle (MDI).

    Erreurs fréquentes

    • G91 resté actif après un retour G28 G91 Z0 : remettez G90 tout de suite.
    • Arc refusé (« arc radius error ») : centres I J incrémentaux alors que la commande attend de l’absolu (G90.1), ou l’inverse.
    • G4 P1 qui attend 1 ms au lieu de 1 s (ou l’inverse) selon le dialecte.
    • Compensation G41 activée sur un mouvement trop court pour la rampe d’entrée.

    FAQ

    G-code Fanuc, Haas, LinuxCNC, grbl : est-ce la même chose ?

    Le cœur (G0–G3, G17–G21, G90/G91, M3/M5…) est commun. Les cycles, les macros, les sous-programmes et les codes machine diffèrent. grbl implémente un sous-ensemble ; vérifiez sa liste de codes supportés.

    Faut-il écrire le G-code à la main ?

    Pour comprendre, corriger et faire de petites opérations en MDI, oui. Pour les pièces, le FAO et un bon post-processeur font le travail.
